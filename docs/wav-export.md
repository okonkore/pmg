# 曲のWAV書き出し

## 操作

メニューまたは「曲の設定・保存」→「曲をWAVに保存」。現在の曲を先頭から1回再生し、現在の音源・音量・リバーブ・ストラム・曲テンポ・音符の強さを含む最終出力を記録する。ループや編集カーソルからの部分再生は書き出しに適用しない。マイク権限は不要。保存曲は書き換えない。

「書き出し開始」後、実時間で曲を再生する。準備中表示・秒数の進捗・中止ボタンを備える。曲末に付ける余韻は12秒（標準）、30秒、60秒。末尾100msに-60dBFSを超える音が残った場合は、余韻を長くして再作成できる旨を表示する。特に音程によって再生時間が伸びるwhole-shell試聴音源は、12秒で必ず完全減衰するとは限らない。

完了したら「WAVを保存」。Windowsのブラウザでは通常のダウンロード操作。対応するiPhone等では「共有・ファイルに保存」を表示し、ユーザーのタップからOSの共有画面を開く。共有が非対応・拒否された場合はWAVリンクを残す。ブラウザが音声を開く場合は、その共有メニュー等で保存する。実機上の具体的な保存先・表示は未検証。

曲の出典・ライセンスがある場合は書き出し画面に表示する。音声の共有・再配布条件は出典を参照。出典情報はWAVの内部メタデータには埋め込んでいない。

## 出力と再生の一致

`mixOutput.output`（音源→ミックス→コンプレッサー→ルームリバーブ→音量→出力ガードの後）にAudioWorkletを並列接続。録音側の出力は無音で、普段の再生出力を二重に加算しない。既存startSongに任意の予約時刻通知を追加し、同じイベント・音源・12音のボイス上限・ノートオフ処理・テンポの積分を使う。曲ごとの強さや新旧リタルダンドもそのまま通る。通常再生には追加の遅延検出制約をかけない。

記録開始・終了はAudioContextのフレーム番号で指定。先頭の準備待ちや再生前の60msは含めない。サンプルレートは現在のAudioContextのものを使用（例：44.1/48kHz）。ステレオ16bit整数PCM、リトルエンディアンRIFF/WAVE。リサンプル・音量正規化・音響モデルの改変はしない。量子化誤差は16bit相当。フルスケールを超えた値は整数範囲へ制限し、実際に発生した場合のみ結果に表示。

書き出し専用に、50ms超のスケジューラ遅れ、音声エラー、AudioContext中断、別操作での停止、非表示化、記録処理エラー、不正なフレーム数を検出した場合は不完全なWAVを提供せず中止する。開始時点で音声スレッドの予約が過去なら同様に中止。画面ロック・アプリ切替中の書き出しは保証せず、画面を開いたまま使う。中止時はノードを切断し、PCMチャンクを解放する。完了ファイルは閉じる／次の書き出し／ページ離脱でURLと参照を解放。

## メモリと長さ

8192フレーム（ステレオPCM16で32KiB）ずつ音声スレッドでエンコードし、バッファをtransferしてメイン側に蓄積する。全曲Float32配列は作らない。WAV上限64MiBを準備前と実サンプルレート確定後、記録中に確認する。上限は余韻込み約380秒/44.1kHz、349秒/48kHz、174秒/96kHz。音声コンテキスト未作成時の初期見積りは48kHzで保守的に判定する。

PCMは最大64MiB。Blob/Fileの生成時コピーはブラウザ実装依存のため、書き出し関連だけで一時的に約128MiB以上になる可能性を見込む必要がある。これに既存の音源キャッシュ・デコード済みバッファ・リバーブ・ブラウザのメモリが加わる。端末全体のメモリ上限を保証するものではない。上限近くの曲の実時間完走・iPhoneでのピークメモリ測定は未実施。

## 検証結果

- `node synth-demo/wav-export.test.cjs`: RIFFサイズ・レート・16bitステレオサンプル値・フレーム境界・上限・中止・開始遅れ・非有限値の拒否。
- `PMG_BROWSER_EXECUTABLE=/usr/bin/chromium node scripts/test_wav_export_browser.cjs`: 従来UI/V2、390×844タッチ環境。加減速、強さ1と0.25、リバーブ付きOrganのWAVをダウンロード。44.1kHz、590336フレーム、13.38630385秒、2361388バイトで一致。曲長2×ln(2)秒＋余韻12秒。末尾は無音、曲後にもリバーブ成分あり。中止→再実行、過大曲の開始拒否、保存データ不変性を確認。
- `test_wav_capture_browser.cjs`: 実AudioWorkletで既知の48kHzステレオ信号12345フレームを記録し、PCM16の期待値と全サンプル差0。実際にPhysical Guitarの1弦E4を生成してWAVを作成（44.1kHz、2152124バイト、ピーク819/32768）。外部停止とAudioContext中断でも不完全ファイルを渡さないことを確認。
- 既存 `playback-timing.test.cjs`、`tempo-changes.test.cjs`、`test_stop_rewind_browser.cjs`、`test_ui_v2.cjs` が成功。

ブラウザテストはLinux Chromium。iPhone Safari、Windowsの実機保存、OS共有シート、全音源・全曲の聴き通し、64MiB近くの完走は未検証。生成音の人による聴き比べは行わず、PCM値・音量・時間・余韻を数値検証した。音響原因調査には触れていない。公開コミットと配備結果はGit履歴・GitHub Actionsを参照。

## ブラウザ資料

AudioWorkletには対応ブラウザと安全なコンテキスト（本番ではHTTPS）が必要。Web Shareはファイル共有能力を確認し、ユーザー操作からのみ呼ぶ。download属性は保存意図とファイル名を指定するが、保存UIはブラウザに依存する。

- https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/audioWorklet
- https://developer.mozilla.org/en-US/docs/Web/API/Navigator/canShare
- https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share
- https://developer.mozilla.org/en-US/docs/Web/API/HTMLAnchorElement/download
